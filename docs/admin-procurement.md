# Выкуп заказов в STEPPE

Откройте `/admin` под аккаунтом администратора. Каталог читает снимки GitHub, не использует SeaTable для товаров.

## Из WhatsApp в магазин

1. Откройте ссылку «Заказ в STEPPE» в новом сообщении клиента: она ведёт на закрытую админку с позициями и размерами.
2. Для старого сообщения вставьте его целиком в поле «Заказ из WhatsApp» и нажмите «Найти товары из заказа». Коды товаров сопоставляются точно; одинаковые модели разных размеров сохраняются отдельными позициями.
3. Проверьте нужный размер, цвет, дату проверки. Показаны цена магазина в исходной валюте, её эквивалент в тенге и цена STEPPE с наценкой. Наличие конкретного размера после заказа могло измениться — это отмечается.
4. «Открыть в магазине» ведёт на проверенный адрес Nike, Puma, Reebok или регионального Uniqlo. Для Uniqlo ссылка содержит группу цены и цвет; размер сверяется рядом со ссылкой, неподдерживаемые параметры автовыбора не выдумываются.
5. Можно скопировать отдельную ссылку или весь список ссылок с размерами. Покупки сайт сам не совершает.

Общий поиск: имя, артикул, код, цвет, исходное JP/KR название; отдельные фильтры раздела, магазина, актуальности. По 24 карточки на страницу.

Сообщение клиента не сохраняется на сервере. Ссылка заказа содержит только идентификаторы и размеры, не ссылки поставщиков. Оба API `/api/admin/catalog` проверяют сессию и административную роль; ответы no-store, Vary: Cookie. В публичном каталоге productUrl остаётся пустым.

## Архив для выкупа

При автоматической публикации исчезнувшие товары переносятся в archivedProducts соответствующего снимка. Они доступны только в административной выдаче, исключены из витрины и отмечены как архив. Срок хранения — 90 дней от последней проверки, максимум 10 000 записей на источник. Архив создаётся начиная с этой версии и не восстанавливает уже утраченные старые позиции.

## Независимый вход владельца

Обычные аккаунты продолжают использовать SeaTable. Для владельца предусмотрены три серверных переменных:

- OWNER_ADMIN_USERNAME — выделенный логин владельца.
- OWNER_ADMIN_PASSWORD_HASH — scrypt-хеш в формате существующего hashPassword.
- OWNER_ADMIN_SESSION_SECRET — случайная строка минимум 32 символа.

Не сохраняйте реальные значения в Git или NEXT_PUBLIC_* переменных. После изменения Production Environment Variables нужен новый deployment. Если параметры не настроены, используется прежний вход SeaTable.

Сессия владельца подписана HMAC, привязана к логину, хешу пароля и секрету; срок 8 часов. Cookie HttpOnly, Secure в production, SameSite=Lax, path=/. Вход и POST административного API требуют свой Origin. Ограничение 8 попыток/15 минут на IP действует в памяти экземпляра; оно не является распределённым лимитом. Поэтому для владельца используйте сгенерированный пароль высокой энтропии и ограничения Vercel Firewall при необходимости. Выход очищает cookie; для отзыва всех сессий смените OWNER_ADMIN_SESSION_SECRET либо парольный хеш и сделайте redeploy. Старые подписанные cookie после ротации не принимаются.

Владельцу показываются закупочные ссылки только после проверки подписи; совпадение одного имени пользователя прав не даёт.
