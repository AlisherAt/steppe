# Одежда в STEPPE

## Разделы

- `/` — кроссовки Nike, Puma, Reebok.
- `/clothing` — спортивная одежда этих трёх брендов из США.
- `/clothing?department=casual` — повседневная одежда Uniqlo Japan и Korea.

Поиск, категории, бренды, размеры, цены и пагинация ограничены выбранным разделом. Корзина общая. Размеры одежды передаются в WhatsApp без пересчёта в обувную систему EU: S/M/L, японские и корейские числовые размеры сохраняются как у производителя. Ссылка поставщика покупателю не показывается.

## Реальные источники

Nike: существующий сборщик расширен типом APPAREL; цены и доступность подтверждаются на странице товара.
Puma: Sale с фильтром clothing, затем проверка страницы каждой модели, доступных размеров и цен.
Reebok: публичный Shopify-каталог Sale, только одежда, доступные варианты с compare_at_price > price.

Uniqlo: оба региональных Commerce API проверены живыми запросами 27 сентября 2026 года. Пример адреса:

`https://www.uniqlo.com/jp/api/commerce/v5/ja/products/E469292-000/price-groups/00`

Для Кореи: `/kr/api/commerce/v5/ko/`. Нужна правильная priceGroup из листинга (00 или 01), а не произвольная группа. Запрос без неё может вернуть перенаправление. Предложенный ранее адрес `uniqlo.comjp/...` некорректен. Параметр `promoCode=sale` во время проверки возвращал пустой результат: сборщик его не использует.

Сборщик обходит весь доступный каталог men/women/kids/baby с пагинацией — с обычными ценами и скидками — и отдельно запрашивает `/stock`. Флаги discount/limitedOffer определяют только пометку скидки, а не попадание в каталог. Каждый размер сопоставляется по l2Id: sales=true, обычная продажа, IN_STOCK и quantity>0. Цвета и варианты длины отделены. Исходное название сохранено в usage и видно продавцу. Исходные размеры сохраняются для выкупа, подписи мерок и возраста переводятся на русский.

### Типы вещей и перевод

Общий модуль `src/lib/uniqlo-labels.mjs` определяет тип по исходному названию JP/KR/EN. HEATTECH, AIRism, флис и пух сами по себе не доказывают тип вещи. Общие breadcrumbs не используются для догадок. Перевод учитывает конкретные существительные: блузка не бюстгальтер, button-down — не пуховик, японские бельевые shorts — не повседневные шорты.

Оставлены боди и комбинезоны, брюки и джинсы, головные уборы, домашняя одежда, жилеты, верхняя одежда, леггинсы, пиджаки, платья и юбки, свитшоты и трикотаж, топы и бельё, футболки и рубашки, худи, шорты. Исключены носки, сумки, ремни, перчатки, варежки, шарфы, платки, очки, зонты, обувь Uniqlo и товары для дома, включая цветы и вазы. Неизвестные типы скрываются до добавления проверенного перевода; общей категории «Одежда» у Uniqlo нет. Названия определяются по данным магазина, автоматического распознавания фотографии нет.

Правило применяется при сборе API/фида, публикации, слиянии неполного обновления, чтении витрины и проверке корзины. Старый отчёт не возвращает запрещённые товары на сайт. Для исправления сохранённых снимков: `node scripts/normalize-uniqlo-catalog.mjs`. Миграция не меняет цены и дату проверки; убранные карточки сохраняются в закрытом архиве администратора для недавних заказов. Повторный запуск безопасен.

Если Uniqlo подтверждает уценку флагом, но не возвращает прежнюю цену, карточка показывает «Скидка» без процента и зачёркнутой цены. Фильтр по минимальному проценту такие товары исключает. Дата окончания акции учитывается, если магазин её предоставил.

robots.txt проверяется перед сбором; 401/403/429 или проверка браузера останавливают источник. Скрытия автоматизации, обхода CAPTCHA, подмены TLS и прокси нет. Доступность из локальной сети не гарантирует доступность из GitHub: ошибки каждого источника видны в отдельной задаче Actions.

## Цены и публикация

`src/lib/server/clothing.ts` проверяет магазин, регион, валюту, размеры, цену и свежесть. USD, JPY и KRW конвертируются по официальному курсу НБК с учётом единицы котировки. В снимке сохраняются исходные цены, валюта, курс и время. Наценка применяется при чтении каталога ровно один раз:

- стоимость до 20 000 ₸: +3000 ₸;
- от 20 000 ₸: +15%;
- после наценки: ещё +3% к полученной сумме, по правилу владельца;
- итог округляется вверх до 500 ₸.

GitHub хранит отдельные `data/catalog/clothing-*.json`. Лимит SeaTable не влияет на эти обновления. Снимки не содержат демотоваров. Неполный обход сохраняет ранее проверенные свежие товары, не продлевая время проверки. Через 36 часов без подтверждения товар скрывается. Пустой результат очищает источник только при подтверждённом полном обходе; ошибки не затирают каталог.

Первая публикация: ограниченный живой обход Nike, Puma и Uniqlo, полный обход Reebok. Это не заявление о выгрузке всего ассортимента. Плановый запуск обходит доступные страницы до лимита времени 100 минут для US или 175 минут для Uniqlo / 10 000 моделей.

## Автообновление GitHub

Workflow: `.github/workflows/clothing-refresh.yml`, «Обновить одежду STEPPE».
Расписание: `0 7,18 * * *` UTC = 10:00 и 21:00 по Москве. GitHub может задержать запуск по расписанию.
Пять источников выполняются независимо. Публикация использует штатный `GITHUB_TOKEN` с contents:write, сохраняет параллельные коммиты. Vercel автоматически собирает main после публикации снимка.

Ручной запуск: Actions → «Обновить одежду STEPPE» → Run workflow → source=all (или один источник). `verify_only=true` делает короткую проверку до 3 моделей, не удаляя остальные свежие товары. Для полного обновления оставьте false. Отчёты доступны в artifacts 7 дней.

## Локальный запуск

```powershell
npm ci
npx playwright install chromium
npm run scrape:clothing -- uniqlo-jp
node node_modules/tsx/dist/cli.mjs scripts/build-clothing.ts artifacts/clothing-uniqlo-jp/report.json
node scripts/publish-catalog.mjs artifacts/publish-clothing
```

Источники: nike, puma, reebok, uniqlo-jp, uniqlo-kr. Для проверки можно установить CLOTHING_DETAIL_LIMIT=3 и NIKE_DETAIL_LIMIT=3; для полного сбора убрать их. CLOTHING_MAX_MINUTES ограничивает время. Отчёты и диагностические файлы игнорируются Git. Команда публикации изменяет GitHub main; локально использует Git Credential Manager, в CI — GITHUB_TOKEN.

## Необязательный разрешённый фид Uniqlo

Для рабочего публичного API ключи не требуются. Если доступ изменится, можно задать независимо для каждого региона UNIQLO_JP_FEED_URL / UNIQLO_KR_FEED_URL, *_FEED_HOSTS (точный разрешённый хост), *_FEED_PERMISSION (основание доступа), при необходимости *_FEED_TOKEN. URL и токен — GitHub Secrets, HOSTS/PERMISSION — Actions Variables. При наличии URL фид заменяет прямой региональный API и не зависит от открытия сайта.

Контракт JSON: version=1, generatedAt (ISO UTC, не старше 36 часов), complete (true только для полной выгрузки), products. Каждый товар: sku, name, usage (исходное название JP/KR/EN; если отсутствует, используется name), product_url официального регионального товара, image_url, необязательные image_urls/color, checked_at, gender (men/women/kids/unisex), variants. Категорию и русское название вычисляет общий классификатор, неизвестные типы и аксессуары отбрасываются. Каждый вариант: id, size, salePrice, originalPrice (положительные десятичные строки), available=true, checkedAt. Для Uniqlo без скидки originalPrice=null и discount_verified=false. Если скидка подтверждена, но прежняя цена неизвестна: originalPrice=null, discount_verified=true и discountEvidence=discount/limitedOffer у каждого варианта. Все цены в JPY для Японии и KRW для Кореи. Пример структуры и граничные проверки — `tests/clothing.test.ts`.
