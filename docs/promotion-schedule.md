# Обновления по срокам акций

Планировщик запускается дважды в сутки, но не обращается к магазину, если у **всех товаров последнего успешного снимка этого источника** указан ещё не истёкший срок акции. Следующий запрос — при первом запуске расписания после ближайшей даты окончания. Отсрочка ограничена 31 днём от получения данных; более длинные акции перепроверяются ежемесячно.

Пример: все предложения Adidas действуют до 1 октября 2026, 23:59 по Казахстану. После загрузки повторных запросов к этому источнику до этого времени нет. Если один товар заканчивается раньше, проверка назначается по нему. Пустой каталог, неизвестный срок хотя бы одного товара или истёкший срок означают обычное обновление дважды в сутки. Для мультибрендового фида решение принимается по всему источнику: запрос фида сразу получает все его бренды.

## Данные источника

- JSON-фид STEPPE: необязательные `saleStartsAt`, `saleEndsAt` в ISO 8601 с часовым поясом, например `2026-10-01T23:59:00+05:00`. Начало должно предшествовать окончанию. Отсрочка требует `saleEndsAt`.
- Google XML/CSV: стандартный `sale_price_effective_date`, интервал `начало/конец` с часовыми поясами; даты сохраняются в карточке.
- Остальные форматы без явно сопоставленного срока продолжают обычное расписание. `valid_to` партнёрской ссылки, рекомендованная розничная цена, название бренда и рекламный текст не считаются сроком скидки.
- Будущий или завершившийся период не публикуется. Дата окончания не угадывается. Окончание проверяется при чтении каталога и корзины, включая данные из серверного кеша.

## Что видит покупатель

Карточка показывает срок акции и настоящую дату последней проверки. При паузе цена, наличие, размеры, доставка и курс остаются последними полученными — магазин может изменить их раньше заявленного срока. Новые акции до следующего запроса не обнаруживаются. Это сознательный обмен частоты проверки на экономию запросов. Курс и время конвертации остаются видимыми; пауза не выдаётся за успешное обновление.

У предложений без срока действует `OFFER_MAX_AGE_HOURS`. У датированных предложений хранение продлевается до окончания акции (максимум 31 день), даже если обычный TTL короче. По окончании карточка скрывается независимо от успеха следующего запроса. Уже открытая страница обновляется при следующей загрузке каталога; проверка корзины не обращается к магазину.

Страница источников показывает, до какого времени отложены запросы. Cron возвращает `status: deferred` и `nextRefreshAt`; GitHub Actions считает такие пропуски отдельно. Это не ошибка. Дата последней успешной проверки не меняется.

## База данных

SeaTable: поля срока сохраняются в JSON `STEPPE_Offers.payload`, расписание вычисляется из подтверждённого снимка. Изменять структуру базы не нужно.

Supabase (альтернативный провайдер): перед обновлением приложения применить `supabase/migrations/202609240004_promotion_schedule.sql`. Она добавляет `sources.next_refresh_at`, атомарное сохранение следующего срока и фильтрацию истёкших предложений. Существующие записи без срока используют прежнее расписание.

Подключение API или фида всё равно требуется: эти изменения не создают реальные предложения или даты акций.
