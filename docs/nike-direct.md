# Nike US: скидки, размеры и ежедневное обновление

Nike включён в ассортимент STEPPE вместе с Puma и Reebok. Источник `nike-us`, магазин https://www.nike.com, валюта USD. Каталог — https://www.nike.com/w/sale-shoes-3yaepzy7ok.

## Сбор

```sh
npm run scrape:nike -- --authorized
```

Флаг используется только при наличии разрешения магазина, уже подтверждённого пользователем. Планировщики вместо флага читают `SCRAPER_PERMISSIONS_JSON.nike`. Установите Chromium: `npx playwright install chromium`.

Сборщик прокручивает официальный раздел Sale и наблюдает штатные ответы его интерфейса. Отдельные запросы к внутренним API не конструируются. Ссылки всех расцветок собираются по SKU, дубликаты удаляются. Следом браузер открывает каждую карточку.

Наличие подтверждается только после динамической загрузки страницы: JSON-LD должен содержать Offer/InStock, GTIN конкретного размера, цену в USD и URL выбранного SKU. Дополнительно сверяются регион US, данные выбранной расцветки, активный SKU и доступность элементов выбора размера/кнопки Add to Bag. Добавление в корзину Nike и покупка не выполняются. Исходный HTML без информации о наличии и текстовые ответы Agent Reach не считаются достаточным подтверждением.

Публикуются кроссовки с явным снижением цены. Бутсы, шиповки, сандалии, шлёпанцы, ботинки, тапочки, предложения без скидки, закрытые/member-only модели и распроданные размеры исключаются. Фиксированная цена каждого доступного размера сохраняется отдельно. Цена для сотрудников Nike не используется. Jordan из магазина Nike относится к источнику Nike US; имя модели сохраняется.

Размеры переводятся в EU по официальным таблицам [мужских](https://www.nike.com/size-fit/mens-footwear), [женских](https://www.nike.com/size-fit/womens-footwear) и [детских](https://www.nike.com/size-fit/kids-footwear) размеров. Неоднозначные значения пропускаются. В сыром отчёте сохраняется `sourceSize` и GTIN.

Цены проходят обычный расчёт STEPPE: курс USD → KZT, наценка 3 000 ₸ ниже 20 000 ₸ или 12% начиная с 20 000 ₸, округление вверх до 500 ₸. Витрина и корзина используют цены выбранного размера.

## Результаты и ограничения

- `artifacts/nike-live/progress.json` — прогресс и ошибки.
- `artifacts/nike-live/candidates.json` — обнаруженные расцветки.
- `artifacts/nike-live/checkpoint.json` — уже проверенные товары текущего прохода.
- `artifacts/nike-live/result.json` — итог и полнота прохода.
- `artifacts/nike-report.json` — отчёт для загрузки на сайт.

Первый обход 26.09.2026 дошёл до последней страницы раздела с заявленными 866 товарными группами и обнаружил 2 863 ссылки на расцветки. Это число кандидатов, а не количество доступных предложений. Проверка остатков и цен выполняется отдельно.

Контрольный обход в 17:36–17:41 UTC подтвердил все 37 страниц (anchor 0–864 с шагом 24): 2 862 ссылки, все уже входят в первый список; одна расцветка за это время исчезла из выдачи. [Проверка GitHub Actions](https://github.com/AlisherAt/steppe/actions/runs/36259824438) также прошла все страницы и подтвердила цены и наличие трёх пробных карточек. Проверочный запуск не публиковал свой сокращённый список.

Только `discoveryComplete=true`, проверка всех кандидатов и отсутствие ошибок позволяют отметить проход как полностью завершённый. `partial` означает ограниченный проход или ошибки отдельных страниц; численность каталога не выдаётся за все предложения Nike. При 401/403/429 или проверке CAPTCHA сбор прекращается. Ошибочный проход не заменяет последний пригодный снимок.

Для отладки `NIKE_DETAIL_LIMIT=3` ограничивает детали; в расписании ограничение не задано. `NIKE_RESUME_DISCOVERY=1` использует список текущего локального прохода не старше двух часов. Это ручной режим продолжения, не настройка ежедневного обновления.

## Публикация

После успешной сборки сайта с поддержкой Nike:

```sh
node --env-file=.env.scheduler.local scripts/upload-scrape-report.mjs artifacts/nike-report.json
node --env-file=.env.scheduler.local scripts/refresh-site.mjs
```

Большие отчёты отправляются в gzip: до 3 MB по сети и до 24 MB распакованного JSON. Сервер проверяет источник, SKU, домены изображений, свежесть, размеры и цены. Лимит — 10 000 товаров за проход. В SeaTable исходный отчёт хранится блоками до 48 KB, ниже [лимита Long Text в 100 000 символов](https://seatable.com/help/long-text-column/). Завершающая запись содержит количество блоков и SHA-256 всех товаров; незавершённая или повреждённая загрузка не публикуется. Старый формат с одной карточкой на строку поддерживается. Отчёты старше 36 часов удаляются — импорт всё равно не принимает такие цены. Ключи хранятся только в окружении.

## Автоматическое обновление

GitHub Actions: `.github/workflows/nike-refresh.yml`, «Обновить Nike STEPPE», каждый день в 07:00 и 18:00 UTC (10:00 и 21:00 Москва). Нужны существующие `CRON_SECRET`, `STEPPE_SITE_URL` и разрешение `SCRAPER_PERMISSIONS_JSON.nike`. Пробный ручной запуск доступен через Run workflow.

Параметр `verify_only` проверяет каталог и три карточки без загрузки в базу. Для обычного полного обновления оставьте его выключенным. Большой серверный каталог хранится в сжатом виде в Next Data Cache, чтобы варианты размеров не превысили лимит 2 MB на запись.

Windows, отдельная задача без пересечения с Puma/Reebok:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install-local-schedule.ps1 -Nike
```

Задача `STEPPE-Nike-Refresh` запускается в 10:00 и 21:00 по часовому поясу Windows и использует `.env.scheduler.local`. Компьютер должен быть включён, пользователь — в системе. Логи: `artifacts/local-nike-refresh/`. Повторный одновременно запущенный экземпляр блокируется. У облачного и локального проходов разные runId; более свежий подтверждённый снимок выбирается по времени цен, не по времени отправки.

Ручной запуск и Планировщик также разделяют `artifacts/nike-live/collector.lock`: пока ручной сбор работает, плановый запуск отмечается как `skipped`, не отправляя старый отчёт.

## Проверки

```sh
npm test -- tests/nike.test.ts tests/catalog-policy.test.ts tests/retail-scrapes.test.ts tests/scrape-snapshot.test.ts
npm run typecheck
npm run build
```

Фикстура Nike содержит минимальные структурированные данные реально проверенной карточки без отзывов и HTML интерфейса. Тесты отклоняют неподтверждённые размеры, проверяют вложенные массивы JSON-LD, GTIN, регионы, разные цены размеров, перевод в EU и сжатую передачу.
