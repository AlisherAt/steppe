# Каталог через GitHub и Vercel

Актуальная схема с 26 сентября 2026: `CATALOG_PROVIDER=github` (также значение по умолчанию).
SeaTable остаётся для пользователей, сессий и прежней админ-панели. Каталог, фильтры,
проверка корзины и подготовка заказа WhatsApp не обращаются к SeaTable.

## Цена

Для **каждого размера**: исходная валюта → KZT по официальному курсу НБК →
если закупка меньше 20 000 ₸, прибавить 3 000 ₸; от 20 000 ₸ включительно — 15%.
Затем округлить вверх до ближайших 500 ₸. Например: 15 000 → 18 000,
19 999 → 23 000, 20 000 → 23 000, 25 000 → 29 000 ₸.
В Git сохраняются закупочные цены, исходная валюта и курс с датой. Наценка применяется
один раз при чтении. Каталог и WhatsApp используют один расчёт.

## Отбор Nike

Максимум 500 проверенных SKU/расцветок со скидкой и доступными размерами.
Основной критерий — точное отношение `(исходная цена − цена скидки) / исходная цена`
в валюте Nike. При равенстве — более низкая итоговая цена, больше размеров, затем ID.
Это рейтинг скидок, а не неподтверждённая статистика популярности.

Пять диапазонов **итоговой минимальной цены карточки**, включая наценку и округление:
до 15 000 включительно; свыше 15 000 до 25 000; свыше 25 000 до 35 000;
свыше 35 000 до 50 000; свыше 50 000 ₸. Цена конкретного размера может быть выше.
Сначала берём до 100 в каждом. Если в диапазоне 5 товаров, показываем 5, а оставшиеся
95 мест поровну перераспределяем между диапазонами, где ещё есть предложения.
Каждое дополнительное место получает следующая лучшая скидка своего диапазона.
Если всего подходящих товаров меньше 500, публикуется фактическое число.

Первый полный проход: 2 863 проверенных кандидата, 2 181 подтверждённая скидка.
Отбор по новой наценке: 0 / 125 / 125 / 125 / 125, всего 500 Nike.
Puma и Reebok публикуются отдельно без лимита Nike.

## Автоматическое обновление

1. GitHub Actions и локальные задачи Windows запускают существующие сборщики
   в 10:00 и 21:00 Москва (07:00 и 18:00 UTC). GitHub может задерживать cron.
2. `scripts/build-catalog.ts` проверяет отчёт, получает курс НБК, проверяет свежесть
   цен и вариантов, формирует отдельные `nike-us.json`, `puma-us.json`, `reebok-us.json`.
3. `scripts/publish-catalog.mjs` создаёт атомарный коммит этих файлов в `main`
   через GitHub API. Vercel разворачивает новый каталог из коммита.
4. Параллельные публикации повторяются от свежего `main` без force push. Более старые
   наблюдения не заменяют свежие. Локальные незавершённые изменения не коммитятся.

GitHub Actions имеет `contents: write` и использует встроенный `GITHUB_TOKEN`.
Для локального запуска нужен Git Credential Manager с доступом к репозиторию,
либо `STEPPE_GITHUB_TOKEN` с правом Contents: Read and write только для этого репозитория.
Токен хранить только в `.env.scheduler.local`, не в Git и не с префиксом `NEXT_PUBLIC_`.
Сборщик браузера не получает ключи публикации. Существующие разрешения магазинов
`SCRAPER_PERMISSIONS_JSON` по-прежнему обязательны. CRON_SECRET больше не нужен
для публикации GitHub-каталога; прежние защищённые маршруты возвращают 409 в этом режиме.

Ручная публикация уже собранного отчёта:

```sh
node node_modules/tsx/dist/cli.mjs scripts/build-catalog.ts artifacts/nike-report.json --out artifacts/publish-catalog
node scripts/publish-catalog.mjs artifacts/publish-catalog
```

Неудачный или неподтверждённый пустой сбор не стирает последний успешный снимок.
Снимки автоматически перестают отображаться через 36 часов после наблюдения цены,
даже без нового деплоя. Повторная публикация не меняет время проверки магазина.
Отчёты ошибок сохраняются в artifacts GitHub Actions и локальных журналах.

## SeaTable и ручное управление

26.09.2026 SeaTable исчерпала месячную квоту 3 000 API-запросов. Аккаунты и прежнее
управление товарами зависят от её восстановления; каталог и гостевой WhatsApp-заказ — нет.
Автоматический каталог больше не читает ручные публикации/скрытия SeaTable.
Из-за квоты выгрузить прежние ручные записи и скрытия при переключении не удалось:
данные в SeaTable не удалены. После восстановления их следует перенести отдельно.

Пока активен GitHub-каталог, прежние API редактирования возвращают явную ошибку,
чтобы не сообщать об изменениях, которые не видны на витрине. Для ручного скрытия
добавьте ID в `data/catalog/overrides.json` → `hiddenIds` или точный URL в `hiddenUrls`,
сделайте коммит. Сборщики этот файл не изменяют. Поле `products` предназначено для
проверенных ручных карточек в схеме Product с закупочными ценами, свежими размерами
и временем проверки. Секреты и данные покупателей туда записывать нельзя.

Возврат к прежнему хранилищу: `CATALOG_PROVIDER=database` в Vercel, затем Redeploy.
Это не сбрасывает квоту SeaTable и требует отдельного возврата старой схемы публикации.
