# Обновление с компьютера Windows

Задача `STEPPE-Catalog-Refresh` запускается **ежедневно в 10:00 и 21:00
по часовому поясу Windows**. При установке на компьютере владельца это
`Russian Standard Time` (Москва, UTC+3). После изменения часового пояса Windows
повторно запустите установщик, чтобы обновить привязку времени.

Компьютер должен быть включён, пользователь — войти в Windows. Блокировка
экрана допустима, выход из учётной записи — нет. Пароль Windows в задаче
не хранится. Окно PowerShell скрыто, права администратора при запуске не нужны.
После пропущенного времени Windows может выполнить задачу при восстановлении
условий запуска (`StartWhenAvailable`, требуется сеть). Пробуждение выключенного
компьютера не настроено. Системный VPN сохраняет своё действие: для выхода через
провайдера его нужно отключить самостоятельно.

## Как работает

1. Проверка секретов, браузера и Python. При первом запуске Chromium устанавливается
   от имени пользователя в `artifacts/local-browsers`; обновления Playwright могут
   потребовать новой загрузки. Проверка TLS не отключается.
2. Сбор всех 15 настроенных магазинов локально без прокси приложения.
   Разрешения берутся из `SCRAPER_PERMISSIONS_JSON`; блокировки магазинов
   и robots.txt продолжают учитываться. Полный каталог не гарантируется:
   действуют ограничения количества карточек и бюджета времени сборщика.
3. Отправка отчёта на `/api/cron/scrape-report`. Повторы отправки используют тот же
   `runId`; повторного обхода магазинов при этом нет.
4. Вызов `/api/cron/refresh` на Vercel: проверенные варианты импортируются в SeaTable,
   цены конвертируются в тенге. HTTP 502 с результатами отдельных источников
   учитывается как частичный результат, а не успех всех магазинов.

Параллельные запуски блокируются задачей Windows и локальным lock-файлом.
Задача ограничена 40 минутами. `success` / `partial` при обновлении хотя бы части
источников завершается кодом 0; инфраструктурная ошибка или отсутствие обновлённых
источников при ошибках — кодом 1. Подробности всегда проверяйте в журнале.

GitHub Actions остаётся доступным **только для ручного запуска**; его автоматическое
расписание удалено, чтобы компьютер и GitHub не публиковали конкурирующие снимки.
На Vercel отдельного Cron нет. Не запускайте GitHub workflow одновременно с локальной задачей.

## Установка на другом компьютере / восстановление

Из корня проекта установите Node.js 22+ и Python 3.12+, затем:

```powershell
npm ci
python -m pip install -r scripts/python-sale/requirements.txt
```

Создайте **игнорируемый Git** файл `.env.scheduler.local`:

```dotenv
CRON_SECRET=тот_же_секрет_что_на_Vercel
STEPPE_SITE_URL=https://steppe-gray.vercel.app
SCRAPER_PERMISSIONS_JSON='{"nike":"ваше действующее согласование"}'
PYTHON_EXECUTABLE="C:/путь/к/python.exe"
```

В `SCRAPER_PERMISSIONS_JSON` укажите существующие подтверждения для всех разрешённых
источников. При текущей установке перенесены уже настроенные 15 подтверждений из
GitHub; новые разрешения не выдумываются. Токен SeaTable локальному планировщику не нужен.
Не перемещайте папку проекта после регистрации: задача ссылается на её абсолютный путь.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install-local-schedule.ps1
Start-ScheduledTask -TaskName 'STEPPE-Catalog-Refresh'
```

Установщик повторно настраивает ту же задачу. `ExecutionPolicy Bypass` действует только
для процесса запуска сценария; системная политика не изменяется.

## Проверка и управление

```powershell
Get-ScheduledTask -TaskName 'STEPPE-Catalog-Refresh'
Get-ScheduledTaskInfo -TaskName 'STEPPE-Catalog-Refresh'
Get-Content artifacts/local-refresh/latest.json
```

- `artifacts/local-refresh/latest.json` — этап, время, число карточек, результат отправки
  и импорта каждого источника. `running` означает, что задача ещё выполняется.
- `artifacts/local-refresh/*.log` — подробные журналы каждого запуска.
- `artifacts/local-refresh/*.scrape.json` — сохранённый снимок сбора.
- `artifacts/diagnostics/` — снимки ошибок сайтов последнего сбора.

Артефакты и `.env.scheduler.local` не коммитятся. Архивы журналов сохраняются локально;
при необходимости удаляйте старые завершённые журналы вручную.

При смене `CRON_SECRET` обновите его и в `.env.scheduler.local`, и на Vercel.
Ручной запуск того же процесса без Планировщика: `node scripts/local-refresh.mjs`.
Отключение: `Disable-ScheduledTask -TaskName 'STEPPE-Catalog-Refresh'`.
