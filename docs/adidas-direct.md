# Прямой сбор adidas US

Реализован отдельный браузерный адаптер без CJ/Impact: `scripts/adidas-details.mjs`.
Источник каталога — https://www.adidas.com/us/shoes-sale, идентификатор сборщика `adidas`,
идентификатор импорта в витрину `adidas-us`. Отчёты поступают через существующий
защищённый upload в SeaTable, затем обрабатываются `/api/cron/refresh`.

## Проверенное состояние

Прямой запуск в этой среде 25.09.2026 получил `PAGE_HTTP_403`, товаров — 0.
Работа извлечения и проверок подтверждена на искусственных тестовых страницах,
а не успешным импортом с adidas. Селекторы PDP необходимо подтвердить на живом
магазине после получения технического допуска. Адаптер нельзя считать работающим
источником реальных предложений, пока не пройдёт такой запуск.

Кэш поисковой системы не используется как товарный фид. Обход CAPTCHA, прокси
для смены заблокированного адреса и маскировка браузера не реализованы.

## Как работает

- Читает SKU цвета из адреса карточки, отбирает обувь с явной скидкой.
- На странице товара сверяет регион US, SKU и название; выбирает каждый доступный
  числовой размер и требует подтверждения выбранного состояния и доступной кнопки
  Add to bag. Кнопку покупки не нажимает.
- После выбора сохраняет видимую новую и зачёркнутую цену в USD; исключает диапазоны,
  отсутствие скидки и неоднозначные цены. Промокоды автоматически не применяются.
- Размеры сохраняются в системе US (с M/W/K, когда назначение определено).
  Конвертация US в EU наугад не выполняется; двойные и буквенные размеры пока пропускаются.
- Только подтверждённые варианты проходят серверную проверку и пересчёт в тенге.
  Старые сведения и дубликаты отклоняются. Непроверенные кандидаты остаются частными.
- Проверяется robots.txt, включая запросы fetch/XHR к тому же домену adidas.
  Ограничения доступа останавливают сбор; запрещённый запрос не отправляется.

## Запуск

Используется уже существующее разрешение `SCRAPER_PERMISSIONS_JSON.adidas`.
Нового API-ключа adidas нет. Для полного пути нужны действующие настройки SeaTable,
`CRON_SECRET` в GitHub/Vercel и `STEPPE_SITE_URL`, как у остальных сборщиков.

В GitHub Actions откройте «Обновить каталог STEPPE» → Run workflow → `sources=adidas`.
Обычный запуск по расписанию включает adidas дважды в день: 01:00 и 13:00 UTC.
`ADIDAS_DETAIL_LIMIT` в окружении сборщика задаёт число проверяемых карточек:
по умолчанию 6, допустимо 1–20. Это ограниченная выборка, а не весь каталог.
Время источника ограничено тремя минутами в пределах общего бюджета запуска.

При HTTP 403 нужен согласованный технический допуск со стороны adidas.
После него проверяем артефакт `scraper-report`: реальные variants, разные размеры,
цены и время, затем импорт и отображение в live-каталоге. Само наличие адаптера
или успешный тест на фикстуре не подтверждает подключение магазина.

## Проверки

`npm test` — серверная проверка SKU, доменов, валюты, размеров и цен в тенге.

`npm run test:e2e -- tests/e2e/adidas.spec.ts` — локальные искусственные страницы:
разные цены размеров, недоступный размер, неподтверждённый выбор, блокировка и SKU.

Ранее существовавший пункт партнёрского адаптера adidas заменён прямым `adidas-us`.
Старые `ADIDAS_FEED_*` переменные больше не активируют источник. Если позднее будет
получен настоящий фид, его формат и остатки следует подключать отдельным адаптером.
