# Вход по логину и паролю

Страница `/login`: регистрация, вход, просмотр текущего аккаунта и выход. Каталог публичный. Корзина остаётся локальной для браузера; синхронизация между устройствами не реализована.

## Настройка

Используется существующая SeaTable, независимо от провайдера каталога. Нужны серверные `SEATABLE_API_TOKEN`, `SEATABLE_SERVER_URL`, `SEATABLE_BASE_NAME`, `SEATABLE_WORKSPACE_ID` из `.env.example`. Не добавляйте префикс NEXT_PUBLIC.

Перед деплоем выполните `npm run seatable:setup`: создаются STEPPE_Users, STEPPE_Sessions и STEPPE_AuthAttempts. Права доступа к базе должны быть только у доверенных администраторов. На Vercel дополнительные ключи для авторизации не нужны, если SeaTable уже подключена.

## Поведение

- Логин: 3–32 латинские буквы, цифры или `_`, без учёта регистра.
- Пароль: 12–128 символов; хранится только scrypt-хеш с индивидуальной случайной солью (N=32768, r=8, p=3).
- Случайная сессия 256 бит действует 7 дней; в базе хранится SHA-256 токена. Cookie HttpOnly, SameSite=Lax, Secure и __Host-prefix на production. Выход отзывает сессию в базе.
- POST принимает JSON только с того же origin; ответы авторизации не кешируются.
- Попытки сохраняются в SeaTable: до 8 на логин и 30 на IP за 15 минут. На Vercel используется заголовок IP, перезаписываемый платформой. Истёкшие попытки и сессии очищаются при следующем обращении к соответствующему механизму.
- Дубли логинов блокируют вход, а не выбирают произвольную запись.

## Ограничения

SeaTable не предоставляет атомарного ограничения уникальности и счётчиков: параллельные регистрации одного логина могут создать дубликаты (вход будет заблокирован), а одновременные запросы могут превысить лимит попыток. Для масштабного публичного запуска используйте дополнительное ограничение `/api/auth` на Vercel Firewall и специализированное хранилище авторизации с транзакциями. Данные читаются постранично; текущая реализация рассчитана на небольшой проект.

Восстановление пароля по почте и проверка email не предусмотрены: email не запрашивается. Пользователь видит это до регистрации. Администраторы не должны вручную раскрывать или назначать пароли без проверки владельца.

Проверки: `npm test` (хеширование, вход, выход, срок сессии, дубли, лимит попыток), `npm run build`.
