# Автоматический сбор и публикация

GitHub Actions → «Обновить каталог STEPPE» запускается по cron `0 1,13 * * *`: 06:00 и 18:00 Алматы. GitHub может задержать плановый запуск. Есть Run workflow для ручной проверки. Совместная concurrency-группа предотвращает наложение запусков.

Этапы: проверка robots.txt для 15 брендов → Playwright для разрешённых источников → JSON-артефакт → защищённый POST `/api/cron/scrape-report` → SeaTable → обычное обновление разрешённых товарных фидов. На `/sources` отображается время и результат проверки. Ошибки и отсутствие разрешения не считаются успешным сбором товаров.

## Что необходимо настроить

- Один CRON_SECRET (не короче 32 символов) в GitHub Actions Secrets и Vercel Production.
- Существующие параметры SeaTable на Vercel; `npm run seatable:setup` создаёт STEPPE_Scrapes.
- GitHub Actions Variable `SCRAPER_PERMISSIONS_JSON`: объект с идентификаторами разрешённых источников и ссылкой/номером согласования. Пример структуры: `{"nike":"номер согласования"}`. Значение не должно быть вымышленным. Без него проверяется robots.txt, сбор карточек не запускается. Доступность публичной страницы не означает разрешение на коммерческую публикацию.
- Идентификаторы всех 15 брендов: scripts/scraper-sources.mjs. Селекторы требуют проверки для каждого разрешённого сайта; конфигурация не означает подтверждённую работоспособность. CAPTCHA, 401/403/429 и запрещённые переходы останавливают источник. Скрытые API не вызываются.

## Данные для заказа

Пять полей карточки (SKU, название, изображение, старая и новая цена) не подтверждают остатки и цену каждого размера или склад. Сборщик сохраняет их как частные кандидаты с `size_price_verified:false`; они не попадают в live-каталог. Полный отчёт доступен оператору в SeaTable и артефактах GitHub. Публично показываются только счётчики и время, без ссылок поставщиков.

Для наполнения live-каталога используются проверенные браузерные адаптеры ниже либо разрешённый фид из docs/fixed-price-sources.md. Рыночные котировки и карточки без подтверждения вариантов не публикуются.

## Проверка

### Подключение прокси

Сборщик поддерживает `SCRAPER_PROXY_URL`: `http://host:port`,
`http://user:password@host:port`, `https://host:port` или `socks5://host:port`.
Спецсимволы в логине/пароле должны быть URL-encoded. Проверка TLS остаётся включённой.
Это настройка Playwright, не системные `HTTP_PROXY`/`HTTPS_PROXY`.

Для локального списка задайте `SCRAPER_PROXY_FILE` (один адрес на строку)
и `SCRAPER_PROXY_INDEX` (с нуля, после удаления повторов). Нельзя задавать файл и URL
одновременно. `node scripts/check-scraper-proxies.mjs` проверяет весь файл на доступ
к `https://example.com/` и сохраняет индексы результатов в `artifacts/proxy-check.json`.
Проверка HTTPS не подтверждает страну IP, доступ к магазинам или постоянную работоспособность.
Список храните вне репозитория либо в игнорируемой папке `artifacts/`.

В GitHub Actions используется Secret `SCRAPER_PROXY_URL` с проверенным адресом.
Пустой Secret сохраняет прямое подключение. Прокси применяется к robots.txt и
браузеру сборщика; запросы загрузки отчёта, SeaTable и секреты STEPPE через него не идут.
Один адрес используется на весь запуск: при CAPTCHA/403/429 прокси не меняется,
а недоступность настроенного прокси не приводит к скрытому прямому подключению.
Локальные команды автоматически `.env.local` не читают: задайте переменные в оболочке
или используйте `node --env-file=.env.local scripts/scrape-sales.mjs`.

`node scripts/scrape-sales.mjs` — выполнить проверку всех сайтов и сохранить artifacts/scraper.json.

`node scripts/upload-scrape-report.mjs` — передать отчёт (CRON_SECRET должен быть в окружении).

`npm run test:e2e -- tests/e2e/scraper.spec.ts` — проверить DOM-извлечение на локальной фикстуре без посещения магазинов.

## Puma US: публикация проверенных размеров

Для adidas добавлен [отдельный прямой адаптер](adidas-direct.md). Его интеграция
проверена на тестовых страницах; живой запрос пока получает HTTP 403, поэтому adidas
не включён в список источников с подтверждённым успешным сбором.

Сборщик `scripts/puma-details.mjs` открывает карточку выбранного цвета, сверяет Style ID,
читает таблицу US → EU (DE) из Size Guide этого товара и выбирает каждый доступный размер.
Цена записывается только после выбора, появления IN STOCK и доступной кнопки Add to Cart.
Корзина магазина не изменяется. Промокоды, рассрочка и дата 2050 из JSON-LD не используются.
Размеры без однозначного соответствия EU пропускаются; остаток в штуках не выдумывается.

По умолчанию проверяются первые 12 моделей из текущей выборки (до 100 карточек),
а не весь каталог Puma. `PUMA_DETAIL_LIMIT` — целое от 1 до 30 в окружении сборщика.
Как только набрано достаточно кандидатов Puma, просмотр списка заканчивается и начинается проверка размеров.
Общий предел запуска — 15 минут; Puma получает до 5 минут, другие магазины до 3 минут каждый в пределах общего бюджета. Непроверенные карточки остаются черновиками.
Диагностика ошибок сохраняется в GitHub Actions artifacts на 7 дней.

Публикация работает с SeaTable: `DATABASE_PROVIDER=seatable`, `SEATABLE_API_TOKEN`
и действующий `CRON_SECRET`. Новые ключи Puma не нужны. Существующее разрешение
в `SCRAPER_PERMISSIONS_JSON.puma` должно оставаться включённым.
После сохранения отчёта обычный `/api/cron/refresh` импортирует подтверждённые варианты
через адаптер `puma-us`, конвертирует цены действующим провайдером курса и обновляет витрину.
Снимок заменяется целиком: непроверенные в текущем снимке модели не сохраняются как новые предложения.
Товары и варианты старше 36 часов не импортируются; витрина также учитывает `OFFER_MAX_AGE_HOURS`.

Подтверждается рынок официального магазина США. Физическое расположение склада неизвестно
и не записывается как US. Исходные размеры US, идентификаторы вариантов, цены USD и время
проверки остаются в закрытой таблице STEPPE_Scrapes; витрина использует размеры EU и тенге.
Этот путь пока не поддерживается для Supabase. Остальные адаптеры фидов сохраняют свой механизм.

## Reebok US, On US, Brooks US и FILA Europe

`scripts/retail-details.mjs` содержит отдельные сборщики, `src/lib/server/scraped-retail.ts` — импорт в существующие таблицы SeaTable. Дополнительные ключи для этих публичных страниц не нужны; разрешения `reebok`, `on`, `brooks`, `fila` должны быть включены в `SCRAPER_PERMISSIONS_JSON`. FILA использует официальный европейский магазин fila.de вместо неработающего адреса распродажи США.

- Reebok: опубликованный JSON товара и JSON-LD сверяются с доступными кнопками размеров; денежные значения в центах переводятся в USD. Назначение размера берётся из подписей магазина, а не из суффикса SKU.
- On: после выбора каждого доступного размера проверяются кнопка Add to bag и текущая/старая цена на странице. Сохраняется выбранный цвет.
- Brooks: проверяется выбранный размер, цвет, ширина и доступность Add to cart; цена берётся после переключения. В подписи размера сохраняется ширина, например `US W 7 1B`.
- FILA: цена в EUR берётся из опубликованного варианта размера; `.inactive` и `.soldout` исключаются. Корзина магазина не изменяется.

Размеры сохраняются в исходной системе US или EU, без приблизительного пересчёта. Исходные цены USD/EUR и время проверки сохраняются; KZT рассчитывается настроенным провайдером курса. Обрабатываются первые 6 найденных товаров каждого нового магазина в пределах бюджета, поэтому это проверенная выборка, а не полный ассортимент. Снимки независимы по источникам; отчёт одного магазина не заменяет другой. Публичные карточки и WhatsApp не раскрывают ссылки поставщиков.

Локальная проверка 24.09.2026 подтвердила варианты Reebok, On, Brooks и FILA; работоспособность из GitHub Actions проверяется отдельно по каждому запуску. Skechers публикует карточки, но его robots.txt запрещает запросы выбора варианта `?dwvar`, поэтому цены размеров не считаются подтверждёнными. Nike, adidas, New Balance и другие источники с HTTP 403/429, CAPTCHA или запретом robots сохраняют диагностику; для них нужен доступ, предоставленный магазином, или фид. Разрешение владельца само по себе не снимает техническую блокировку.

Проверка из GitHub Actions 24.09.2026: Puma, Reebok, On, Brooks и FILA автоматически собраны, импортированы в SeaTable и опубликованы. Для ручной диагностики отдельного магазина в Run workflow можно заполнить `sources`, например `puma,fila`; локально это `SCRAPER_SOURCE_IDS`. Неизвестные идентификаторы отклоняются. Плановые запуски всегда проверяют все 15 источников.

Дополнительная диагностика ASICS Outlet Europe: каталог доступен, но JSON-LD указывает размеры `N/A`, а запрос robots.txt вернул HTML вместо правил. Источник не включён как подтверждённый импорт. Актуальная страница Salomon US также вернула HTTP 403.
