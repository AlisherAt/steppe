# Полный сбор распродаж Reebok и Puma

Сборщик `scripts/scrape-sales.mjs` использует отдельный обход коллекций
из `scripts/sale-catalog.mjs` для двух источников:

- Reebok: `https://www.reebok.com/collections/sale?current=1` — публичный JSON
  этой коллекции `/collections/sale/products.json?limit=250&page=N`, после
  проверки robots.txt и валюты открытой страницы. `scripts/reebok-feed.mjs`
  обходит страницы до неполной выдачи, без лимита первых карточек.
  Одежда, аксессуары, тапочки и бутсы исключаются.
- Puma: `https://us.puma.com/us/en/sale/all-sale` с фильтрами Men + Women,
  Shoes, Running + Training, указанными владельцем. При переходе Next
  параметры `filter_*` сохраняются, даже если магазин убрал их из ссылки.
  Ссылки читаются также из исходного HTML: клиентский JavaScript магазина
  может заменить товары последней страницы повтором предыдущей.

Нет прежнего ограничения на первые 6 товаров Reebok и 12 товаров Puma.
Ограничение времени каждого магазина — 45 минут, общего запуска — 110 минут;
GitHub Actions и задача Windows допускают 125 минут с учётом подготовки/публикации.
Расписание сохраняется: 10:00 и 21:00 Москва. Если обход прерван, отчёт явно
содержит `partial`/`INCOMPLETE_COLLECTION`, а не заявление о полном каталоге.

## Подтверждение товаров

Reebok: опубликованный товар типа Shoes, вариант `available: true`, явные
`price` и `compare_at_price` в долларах (не центах), размер из опции Size.
Валюта USD подтверждается страницей магазина. Товары без доступных вариантов
с прямой скидкой пропускаются. Повторная страница или неоднозначные размеры
отмечаются как ошибка. Одежда в общем счётчике магазина не становится обувью.

Puma: точный артикул цвета, видимые цены, таблица US/EU самого товара,
доступные размеры интерфейса и встроенные магазином данные `__NEXT_DATA__`.
Цена относится к выбранному цвету; наличие — к каждому его размеру.
При отсутствии однозначных встроенных данных остаётся проверка посредством
выбора каждого размера в интерфейсе. Внутренние API напрямую не опрашиваются.

В обоих случаях нужны старая цена больше новой, доступный размер и фиксированная
цена. Промокоды, условные скидки и рекламные проценты не применяются автоматически.
Неуспешные детали и товары без подтверждённой скидки не становятся live-карточками.
При HTTP 401/403/429 или проверке доступа обход останавливается без её преодоления.

## Диагностика

- `artifacts/diagnostics/puma-collection.json` и `reebok-collection.json`:
  увиденные карточки, кандидаты, заявленное число товаров и полнота обхода.
- `artifacts/scraper.json`: подтверждённые карточки и причины пропуска деталей.
  Промежуточный результат сохраняется после каждого проверенного товара.
- `SCRAPER_RESUME_REPORT` — необязательный локальный путь к отчёту для продолжения
  прерванной ручной проверки. Только подтверждённые данные моложе двух часов
  и совпавшая ссылка; при наличии цен в текущем списке они также сверяются.
  Время исходной проверки сохраняется. Плановые запуски не задают эту переменную.

Сервер принимает до 1500 карточек в отчёте, прежний предел 100 на источник снят.
Загрузка через `/api/cron/scrape-report` и публикация через `/api/cron/refresh`
используют существующий `CRON_SECRET`. Секреты не передаются сборщику магазинов
локальным планировщиком. Дубли определяются по артикулу; удалённые администратором
карточки остаются скрытыми. Наценка +3000 ₸ / +12% применяется при выдаче каталога.
После обновления сервер сбрасывает кэш каталога и статусов источников;
следующий запрос страницы получает свежие карточки. На странице выводится
12 товаров, остальные доступны через переключение страниц внизу каталога.
