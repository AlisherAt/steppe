# Agent Reach в STEPPE

Подключён [Panniantong/Agent-Reach](https://github.com/Panniantong/Agent-Reach), версия 1.5.0, коммит `a19a171fa980a0785849596492e0af4db800c82f`. Код закреплён в `scripts/agent-reach/requirements.txt`. Установка идёт из GitHub, а не из одноимённого пакета PyPI.

Agent Reach — набор инструментов доступа к информации. Для этих магазинов используется его настоящий Python-класс `WebChannel.read()`, читающий публичную страницу через Jina Reader. Специальных API Nike/Adidas этот пакет не предоставляет.

## Установка и запуск

Нужны Node.js 22+, Python 3.10+ и установленные npm-зависимости STEPPE.

```sh
npm run reach:install
npm run reach:doctor
npm run scrape:reach -- --authorized
```

`--authorized` подтверждает, что у оператора есть разрешение магазинов на такой сбор. В этой задаче пользователь ранее сообщил о полученном разрешении. Проверка robots.txt остаётся обязательной.

Установка создаёт отдельное окружение `artifacts/agent-reach-venv`, проверяет зависимости через `pip check` и импорт пакета. Системный Python и конфигурация других агентов не меняются. `reach:doctor` проверяет импорт и версию, **не доступность Nike/Adidas в интернете**. Для неё нужен `scrape:reach`.

Ограниченный запуск только Nike в PowerShell:

```powershell
$env:REACH_SOURCE_IDS='nike'
$env:REACH_DETAIL_LIMIT='3'
npm run scrape:reach -- --authorized
```

По умолчанию проверяются Nike US и Adidas US; три разные модели каждого магазина. `REACH_DETAIL_LIMIT` принимает 1–10. Проверяется одна страница каталога, это не выгрузка всего ассортимента. Для интерпретатора установки можно задать `PYTHON_EXECUTABLE`.

## Что сохраняется

- `artifacts/agent-reach/latest.json` — последний диагностический отчёт.
- `artifacts/agent-reach/<runId>/report.json` — конкретный проход.
- `observations.csv` — извлечённые поля, в том числе неполные наблюдения.
- Markdown-ответы магазинов, robots.txt, SHA-256 ответов — для отладки.

Отчёты имеют отдельный путь и не перезаписывают `artifacts/scraper.json`, используемый работающим сборщиком Puma/Reebok. Время получения страницы не означает свежесть кэша Jina: `freshness_verified` всегда `false`. `lastSuccessfulCheck` — успешное завершение чтения выбранных страниц, не обновление остатков.

## Публикация и расписание

Интеграция установлена как инструмент сборщика в репозитории. Python запускается на компьютере/runner, не внутри функций Vercel. Ключи SeaTable, Vercel, GitHub, `CRON_SECRET` и переменные прокси не передаются процессу чтения. URL ограничены публичными страницами двух магазинов; cookie браузера не импортируются.

Кандидаты сохраняют `size_price_verified: false`; автоматическая загрузка на сайт и включение в расписание пока не активированы. Существующие обновления Puma/Reebok продолжают работать независимо. Прежде чем подключать эти данные к импорту, необходима проверка каждой доступной вариации и её фиксированной цены, а также свежести данных. Нельзя заменить эти флаги на `true` лишь потому, что в тексте есть цена и размер.

Для Adidas потребуется доступ, который действительно возвращает страницы магазина: например, согласованный технический доступ либо официальный товарный фид. Agent Reach не устранил эту проблему. Stealth, ротация прокси, обход CAPTCHA и альтернативные запросы после отказа доступа в проходе не используются.

На одну страницу приходится один запрос Reader; пауза не менее двух секунд и не меньше Crawl-delay. Ошибки 403/429, CAPTCHA, смена источника, рекламный ответ и предупреждения о неполной загрузке прекращают проход магазина. Ошибка не удаляет работающий каталог. Выход CLI: 0 — чтение завершено, 2 — есть ошибка источника, 1 — ошибка запуска/настройки. Код 0 не означает, что появились пригодные для публикации предложения.

## Проверки

```sh
npm test -- tests/agent-reach.test.ts
npm run typecheck
```

Тестируются robots.txt, защита от подмены URL, вложенные 403/429, рекламные ответы, дедупликация, ограничение количества деталей, цены и процент скидки, исключение Sold Out, отсутствие ложного подтверждения размеров и изоляция секретов.
