# Предоставленные Python-парсеры в STEPPE

Десять файлов брендов и `models.py` взяты из присланного пользователем комплекта.
Методы `parse_card` используются в плановом сборе. `base_scraper.py`, `main.py`
и зависимости адаптированы к существующему проекту.

## Схема работы

1. `scripts/scrape-sales.mjs` проверяет разрешение и robots.txt, открывает магазин
   через Node.js Playwright, ожидает JavaScript, выполняет скролл и пагинацию.
2. При `PYTHON_SALE_PARSERS=1` снимок отрисованного DOM передаётся через stdin в
   Python. `scripts/python-parsers.mjs` ограничивает время процесса и размер данных.
3. Python запускает соответствующий предоставленный `parse_card`. BeautifulSoup
   используется только для уже отрисованного HTML, не для сетевого запроса к SPA.
   JavaScript и внешние ресурсы снимка не исполняются и не загружаются.
4. Результат объединяется с существующим извлечением карточек. Требуются SKU,
   изображение, конкретные цены и скидка. Диапазоны и неоднозначные цены отклоняются.
5. Из второй версии комплекта добавлен переход на страницы до шести кандидатов
   в пределах бюджета источника. Python читает SKU из JSON-LD (в том числе @graph)
   и подписи размеров. Недоступные варианты и связанные товары исключаются.
   До этого этапа SKU может отсутствовать; без настоящего SKU карточка не отправляется.
   Размеры сохраняются как частные `size_candidates`, без утверждения цены/наличия.
   Эти карточки имеют `size_price_verified:false` и остаются частными кандидатами.
   У adidas есть отдельный этап проверки вариантов. Для остальных новых брендов
   необходимо подтвердить цену и наличие каждого размера, прежде чем публиковать.
6. Существующий upload сохраняет отчёт в SeaTable. Подтверждённые предложения
   импортируются в live-каталог; расписание по-прежнему два раза в день.

Файлы содержат предполагаемые селекторы: автоматическая проверка всех десяти
модулей на фикстурах не доказывает успешный сбор десяти живых магазинов.
HTTP 403/429 и CAPTCHA по-прежнему останавливают источник.

## Установка и запуск

Python 3.12 и существующий Node.js-проект:

```powershell
python -m pip install -r scripts/python-sale/requirements.txt
$env:PYTHON_SALE_PARSERS='1'
$env:SCRAPER_SOURCE_IDS='adidas'
node scripts/scrape-sales.mjs
```

Нужен действующий `SCRAPER_PERMISSIONS_JSON`; уже согласованные разрешения остаются
в GitHub Actions Variables. `PYTHON_EXECUTABLE` позволяет указать путь Python,
например из виртуального окружения. Браузер устанавливается существующей командой
`npx playwright install chromium`; второй Python-браузер не нужен.

В GitHub Actions Python и зависимости устанавливаются автоматически, флаг включён.
На Vercel Python устанавливать не нужно: туда отправляется проверяемый JSON-отчёт.
Имена `new_balance` и `under_armour` сопоставлены с `newbalance` и `underarmour`
существующего реестра.

## Проверки и результат

```powershell
python -m unittest discover -s scripts/python-sale -p 'test_*.py'
npm run test:e2e -- tests/e2e/adidas.spec.ts
```

Общий результат — `artifacts/scraper.json`, ошибки и снимки — `artifacts/diagnostics`.
Первоначальный `main.py` с самостоятельным выходом в сеть заменён интеграционным
запуском через stdin; пустой результат больше не выдаётся за подтверждение наличия.
Рекомендации из исходного README по обходу блокировок не применялись.
