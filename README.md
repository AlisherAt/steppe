# STEPPE — кроссовки рынка США

Основной источник: StockX через KicksDB (market=US). Текущие цены в USD пересчитываются в KZT, показываются артикулы и размеры EU по указанной цене. Неподтверждённые скидки не отображаются. Проверка доставки не требуется. [Правила импорта](docs/kicksdb.md).

Исторические инструкции партнёрских скидочных фидов ниже сохраняются для дополнительных источников; ограничения KZ относятся к этим адаптерам, а не к KicksDB.

# STEPPE — скидки на кроссовки

Полное приложение на **Next.js 16 / React 19 / TypeScript**, рассчитанное на **Vercel + SeaTable** (Supabase Postgres поддерживается как альтернативный провайдер). Интерфейс на русском, цены в тенге. Авторизация покупателей и собственная оплата не нужны: покупка происходит у продавца.

## Что работает

- Адаптивный каталог, поиск, фильтры по бренду, размеру EU, полу, назначению, цене, скидке и магазину; сортировка и пагинация. Состояние фильтров сохраняется в URL.
- Карточки с фотографиями, исходной/акционной ценой в тенге, размерами, скидкой, ссылкой и временем проверки. Детали показывают источник курса и время пересчёта.
- Корзина в localStorage: выбор размера, удаление, восстановление после перезагрузки, синхронизация между вкладками. Перед переходом к живому предложению проверяются цена, размер, свежесть и состояние источника.
- Адаптеры JSON, YML, Awin CSV, Google Merchant XML/CSV (также gzip); eBay Browse API с автоматическим OAuth. Профили FARFETCH, YOOX, Tennisnuts, Nike, Adidas и партнёрских сетей. Каталог распознаёт 78 брендов и принимает новые марки из фидов. Чужие CAPTCHA, ограничения и логины не обходятся.
- Региональный допуск: live-предложения только из подтверждённой выгрузки с доставкой KZ либо выборки eBay с `deliveryCountry:KZ`. Основание и время проверки сохраняются. У eBay принимаются только новые товары с STP-скидкой и рейтингом продавца от 98% / 100 отзывов.
- Проверка данных, дедупликация, таймауты и до трёх попыток при сетевых/временных ошибках. В SeaTable публикуется только полностью записанный и проверенный снимок; в Supabase используется транзакция. Источники обновляются независимо.
- Таблицы предложений, источников и запусков; исходные цены и курсы сохраняются. SeaTable доступна только серверу по API-токену. Для Supabase включён RLS.
- Для SeaTable добавлен GitHub Actions workflow в 01:00 и 13:00 UTC (06:00 и 18:00 Алматы), вызывающий защищённый маршрут Vercel. Нужен одинаковый CRON_SECRET в Vercel и GitHub. Supabase Cron оставлен альтернативой.
- Официальный XML-провайдер НБРК, ручной провайдер и настраиваемый авторизованный JSON-провайдер, пригодный для разрешённого API Kaspi.
- Отдельный демокаталог: условные цены/названия и фотографии Unsplash явно обозначены; демоданные никогда не записываются в live-таблицы.

## Фактический статус интеграций

**НБРК:** проверен реальным запросом 24.09.2026; XML получен и разобран, дата курса сохранена. Команда для собственной проверки: `npm run check:rates`. Сеть и доступность внешнего сервиса всё равно могут меняться.

**Kaspi:** авторизованный общедоступный endpoint курсов не подтверждён и не подключён. НБРК нигде не выдаётся за Kaspi. Для подключения Kaspi потребуются официальный/разрешённый URL, документация формата и право использовать курс; настройка описана в [docs/rates.md](docs/rates.md).

**Дополнительные партнёрские фиды:** live-фиды пока не подключены — в окружении нет одобренных партнёрских доступов, URL и токенов. Транспорт, парсеры, преобразование, загрузка в базу и чтение каталога реализованы и проверены тестовыми ответами. Для активации нужен разрешённый фид одного из поддерживаемых форматов или production-ключи eBay. Проверенные альтернативы и точные ограничения доставки — в [docs/sources.md](docs/sources.md); контракты — в [docs/feeds.md](docs/feeds.md). Доставка в страну и право получать данные проверяются отдельно: одно не означает другое.

**SeaTable:** авторизация, создание таблиц и операции чтения/записи проверены в базе Steppe. Созданы три служебные таблицы; источник kicks-stockx регистрируется автоматически. Первый импорт KicksDB: 22 модели рынка США. Production и контрольный запуск GitHub Actions успешно проверены 24.09.2026. Инструкция: [docs/seatable.md](docs/seatable.md).

## Локальный запуск

Нужны Node.js **22.12+** (проверено на Node 24) и npm. В папке проекта:

```sh
npm ci
```

Скопируйте `.env.example` в `.env.local`. В PowerShell:

```powershell
Copy-Item .env.example .env.local
```

Без секретов приложение уже запускается с отдельным демокаталогом:

```sh
npm run dev
```

Откройте [localhost:3000](http://localhost:3000). При настроенном выбранном провайдере начальным режимом становится реальный каталог. Для SeaTable нужен `SEATABLE_API_TOKEN`; для Supabase — `DATABASE_PROVIDER=supabase`, `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`. Ошибка БД показывает ошибку, а не подставляет демотовары.

## База SeaTable

Основное подключение: **[пошаговая инструкция SeaTable](docs/seatable.md)**. Для существующей базы Steppe таблицы уже подготовлены. Supabase SQL-миграции и Vault для SeaTable не требуются.

## База Supabase — только альтернативный провайдер

1. Создайте проект Supabase.
2. Выполните **по порядку все пять файлов** из `supabase/migrations` в SQL Editor нового проекта: `202609240001_initial.sql`, `202609240002_partner_sources.sql`, `202609240003_delivery_kz.sql`, `202609240004_promotion_schedule.sql`, `202609240005_us_market.sql`. Альтернатива: `supabase db push`. В существующей базе примените только ещё не выполненные миграции. Третья сохраняет, но скрывает прежние предложения без подтверждения доставки KZ.
3. В `.env.local` укажите `SUPABASE_URL` и серверный `SUPABASE_SERVICE_ROLE_KEY` (Supabase Project Settings → API). Подходит серверный service-role ключ; не используйте anon/publishable ключ. Не добавляйте префикс `NEXT_PUBLIC_`.
4. Создайте случайный `CRON_SECRET` длиной не менее 32 символов, например `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`.
5. Настройте разрешённые фиды по инструкции ниже. Без фидов live-каталог остаётся пустым.

Публичные таблицы защищены RLS без клиентских политик. Только сервер с service-role вызывает RPC и читает таблицы. Данные каталога выдаются через `/api/catalog` с проверкой параметров. Журналы и токены не выдаются публичным API.

## Деплой на Vercel

1. Загрузите проект в свой Git-репозиторий и импортируйте его в Vercel.
2. Framework: **Next.js**; Root Directory: корень этого проекта; Node.js: **24.x** либо поддерживаемый 22.x. Build command: `npm run build`, install: `npm ci`.
3. Перенесите серверные переменные из `.env.local` в Vercel Environment Variables для Production. Реальные `.env` файлы исключены из Git.
4. Укажите точные домены картинок в `PRODUCT_IMAGE_HOSTS`. Они попадают в Next Image allowlist на этапе сборки, поэтому после изменения нужен новый deploy.
5. Включите **Fluid Compute**, лимит функции обновления — 300 секунд (задан в коде и vercel.json). Выполните Deploy. Проверьте `/`, `/brands`, `/sources`, `/about` и `/api/catalog?mode=live`.
6. Настройте GitHub Actions по [инструкции SeaTable](docs/seatable.md) и выполните контрольное обновление. Для Supabase можно использовать расписание ниже.

Встроенный Vercel Cron не включён в `vercel.json`. По [документации Vercel](https://vercel.com/docs/cron-jobs/usage-and-pricing), частые задачи ограничены на Hobby; расписание выполняет GitHub Actions (или Supabase Cron для альтернативного провайдера). Для коммерческого применения отдельно проверьте условия выбранного тарифа Vercel.

## Обновления дважды в день

**SeaTable:** используйте .github/workflows/refresh.yml и [инструкцию настройки GitHub Actions](docs/seatable.md). Дальнейшие шаги этого раздела относятся только к **Supabase**.

1. В Supabase включите расширения **pg_cron**, **pg_net** и **Vault** (Dashboard → Database → Extensions; Vault также доступен отдельным разделом).
2. Через интерфейс Vault добавьте секреты `steppe_site_url` (production URL без завершающего `/`) и `steppe_cron_secret` (то же значение, что `CRON_SECRET` в Vercel).
3. Выполните `supabase/schedule.sql`. Именованная задача `steppe-refresh-twice-daily` вызывает `POST /api/cron/refresh` в 01:00 и 13:00 UTC. Повторный запуск SQL обновляет ту же задачу.
4. Production endpoint должен быть доступен для Supabase. Если Vercel Deployment Protection закрывает его, настройте авторизованный доступ для планировщика или используйте открытый production-домен. Не выключайте проверку `CRON_SECRET`.
5. Выполните первый запрос вручную (PowerShell; секрет вводится локально):

```powershell
$cronSecret = Read-Host 'CRON_SECRET'
Invoke-RestMethod -Method Post -Uri 'https://ВАШ-ДОМЕН/api/cron/refresh' -Headers @{ Authorization = "Bearer $cronSecret" }
```

Успешный HTTP 200 с `needs_configuration` означает, что запрос принят, **а фид ещё не подключён**. Успешная загрузка конкретного источника возвращает `status: success`, число карточек и меняет время проверки на `/sources`.

При любой ошибке источника endpoint возвращает 502; при общей проблеме — 503. Проверять нужно и HTTP-результат, и `results`. Временные ошибки повторяются внутри задачи (до трёх попыток). 401/403, невалидные или слишком старые фиды не повторяются в текущем запуске. При длительном `Retry-After` задача ждёт следующего расписания; блокировки не обходятся.

Смотрите `public.refresh_runs`, `sources.last_attempt_at`, `sources.last_success_at` и `net._http_response`. `cron.job_run_details` отражает постановку HTTP-запроса в очередь, а не успех загрузки каталога. Время обработки ограничено 300 секундами Vercel-функции, блокировка — 360 секундами. До четырёх магазинов обрабатываются параллельно; после 220 секунд новые загрузки не начинаются и возвращают `REFRESH_BUDGET_EXHAUSTED`. Следующий запуск отдаёт приоритет давно не проверенным источникам. Если бюджет регулярно исчерпывается, разделите расписание/воркеры; нельзя считать пропущенные магазины обновлёнными.

Лимит одного полного фида — 20 MB распакованных данных, до 20 000 исходных строк XML/CSV и до 1000 подходящих товаров. Превышение отклоняет загрузку целиком. eBay — отдельно обозначенная выборка до 200 результатов поиска, не весь маркетплейс. Все импортированные карточки этой выборки перепроверяются при каждом запуске; отсутствующие в новом снимке скрываются. Более крупные выгрузки разделяйте на независимые источники с устойчивым составом (например, по брендам).

## Добавление и остановка магазинов

SeaTable: включите checkbox `paused` у магазина в таблице `STEPPE_Sources`. Supabase: пауза через SQL Editor:

```sql
update public.sources set paused = true where id = 'nike';
-- Возобновить:
update public.sources set paused = false where id = 'nike';
```

Пауза исключает магазин из каталога и обновлений. Возобновление возвращает только ещё актуальные предложения. Для нового магазина задайте `ADDITIONAL_SOURCES_JSON` и переменные его префикса; запись `sources` создаётся автоматически при обновлении. Примеры — в [docs/sources.md](docs/sources.md). Реестр расположен в `src/lib/server/sources.ts`. Для другого протокола реализуйте `SourceAdapter.fetchProducts(): Promise<FeedProduct[]>`; товары должны содержать подтверждение доставки KZ. Частично скачанный фид не должен очищать действующие товары.

## Проверки

```sh
npm test
npm run typecheck
npm run build
npx playwright install chromium
npm run test:e2e
```

Unit-тесты проверяют конвертацию, скидки, фильтры, дедупликацию, сохранение корзины, свежесть курса, номинал НБРК и ограничения URL. Интеграционные тесты выполняют саму SQL-миграцию и RPC в PGlite: транзакции, блокировки, upsert, деактивацию, ошибки, паузы и доступ. Playwright проверяет реальный интерфейс, мобильную ширину, перезагрузку корзины, пустые/ошибочные состояния и разделение live/demo. Запускайте браузерные тесты с пустыми Supabase-переменными; они рассчитаны на автономный деморежим.

## Устройство проекта

- `src/app` — страницы и HTTP API.
- `src/components` — каталог, карточка, оболочка и корзина.
- `src/lib/server` — только сервер: база, адаптеры, курсы, сеть, обновления.
- `src/lib` — типы, расчёты, фильтры, localStorage и отдельные демоданные.
- `supabase/migrations` — структура БД, RLS и транзакционные функции.
- `supabase/schedule.sql` — расписание с Vault.
- `docs` — контракты фидов и валютных провайдеров.
- `tests` — unit, Postgres и browser tests.

KicksDB импортирует реальные модели и цены рынка США. Прямые партнёрские фиды Nike и Adidas пока не подключены. Демофотографии Unsplash иллюстративны и не подтверждают модель, наличие или скидку.

### Экономия запросов во время акций
Сроки скидок управляют паузами источников: [правила и формат данных](docs/promotion-schedule.md). SeaTable не требует миграции; для Supabase примените миграцию 202609240004.

### KicksDB
Серверный клиент и проверка доступа: npm run check:kicks. [Доступные данные и ограничения публикации](docs/kicksdb.md).

### Запуск каталога реальных скидок
Для наполнения требуется доступ к фиду: [точные условия и готовый запрос магазину](docs/live-catalog-activation.md). Браузерные тесты используют отдельный порт 3100, каталог сборки .next-e2e и отключённые подключения к рабочей БД.
