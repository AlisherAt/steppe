# STEPPE — описание проекта

Актуализировано: **25 сентября 2026 года**.

- Сайт: [steppe-gray.vercel.app](https://steppe-gray.vercel.app/).
- Репозиторий: [AlisherAt/steppe](https://github.com/AlisherAt/steppe).

## 1. Назначение

STEPPE — русскоязычный каталог кроссовок со скидками из магазинов США и Европы
для аудитории Казахстана. Сервис собирает предложения, проверяет цены и размеры,
пересчитывает стоимость в тенге и помогает сформировать заказ продавцу через WhatsApp.

Для публикации нужны фиксированные цены доступных размеров. Котировки торгов,
минимальная ставка на маркетплейсе и неподтверждённые скидки не считаются ценой выкупа.
Регион магазина не является подтверждением физического расположения склада.

## 2. Возможности для покупателя

- Каталог с изображениями, брендом, названием, выбором размера и скидкой.
- Отображение исходной и сниженной стоимости в казахстанских тенге — ₸.
- Поиск и фильтры по бренду, размеру, полу, категории, цене, скидке и источнику.
- Сортировка по новизне, размеру скидки и цене; постраничный просмотр.
- Разные цены для разных размеров, если их предоставляет магазин.
- Корзина с выбором размера, удалением товаров и сохранением между перезагрузками.
- Регистрация, вход по логину и паролю, выход из аккаунта.
- Формирование сообщения в WhatsApp со списком выбранных товаров и размеров.
- Сведения об актуальности предложений и состоянии источников.
- Адаптивный интерфейс для телефона и компьютера, состояния загрузки и ошибок.

Оформление через WhatsApp требует настроенного `WHATSAPP_ORDER_PHONE`.
Перед формированием ссылки сервер повторно проверяет товары и выбранные размеры.
Сайт не проводит банковский платёж: дальнейшее оформление происходит в переписке
с продавцом. Ссылки на товары поставщиков обычным покупателям не выдаются.

## 3. Технологии

- **Next.js 16, React 19, TypeScript** — интерфейс и серверные API.
- **Vercel** — размещение сайта и серверных обработчиков.
- **SeaTable** — действующий основной провайдер базы данных.
- **Node.js и Playwright / Chromium** — открытие динамических страниц магазинов.
- **Python** — предоставленные парсеры десяти брендов, работающие над снимками DOM.
- **BeautifulSoup** — разбор HTML внутри Python-слоя; браузером управляет Node.js.
- **Zod** — проверка входящих данных и товарных отчётов.
- **decimal.js** — расчёты денежных величин.
- **Vitest и Playwright Test** — автоматические проверки.
- **GitHub Actions и Планировщик Windows** — два независимых места запуска сборщика.

Supabase сохранён в коде как альтернативный провайдер. Текущая рабочая схема
прямого импорта из браузерных сборщиков использует SeaTable.

## 4. Сбор и публикация товаров

Последовательность обработки:

```text
Магазины США и Европы
    ↓
Сборщик на компьютере / сборщик в GitHub Actions
    ↓
Проверка robots.txt → каталог → страницы товаров → размеры и цены
    ↓
JSON-отчёт с уникальным runId
    ↓
Защищённый API Vercel → STEPPE_Scrapes в SeaTable
    ↓
Выбор свежего подтверждённого снимка каждого магазина
    ↓
Пересчёт в KZT → публикация предложений → каталог STEPPE
```

Каждый магазин имеет отдельный адаптер. Ошибка одного источника не останавливает
обработку остальных. Сборщик сохраняет диагностику, снимки проблемных страниц и
время проверки. Запросы ограничены таймаутами, количеством карточек и общим бюджетом
времени: текущий обход является выборкой, а не гарантированной выгрузкой всего ассортимента.

Карточка без проверенных вариантов сохраняется как кандидат с
`size_price_verified: false` и не публикуется как живое предложение.
Система не обходит CAPTCHA, ответы об ограничении доступа и запреты robots.txt.

### Два сборщика одновременно

- **Компьютер владельца:** задача Windows `STEPPE-Catalog-Refresh`, ежедневно
  в **10:00 и 21:00**. Настроенный часовой пояс — **Москва, UTC+3**.
- **GitHub Actions:** workflow «Обновить каталог STEPPE», cron `0 7,18 * * *`,
  то есть **10:00 и 21:00 по Москве**. Возможны задержки со стороны GitHub.

Локальный запуск использует подключение компьютера без прокси приложения.
Включённый системный VPN продолжает влиять на выходной IP.
Компьютер должен быть включён, иметь интернет и активный вход пользователя в Windows;
экран можно блокировать. Облачный запуск не зависит от включения компьютера.

Два сборщика отправляют независимые отчёты. Для каждого магазина выбирается один
подтверждённый снимок по времени наблюдения цен. Ошибочный, пустой или неподтверждённый
отчёт не перекрывает свежие проверенные данные второго сборщика. Размеры и цены
разных снимков не объединяются. Повторный импорт не продлевает актуальность наблюдений:
предел для импортируемых данных — **36 часов**.

## 5. Источники и фактическое покрытие

В конфигурации браузерного сборщика предусмотрены **15 брендов**:

Nike, adidas, Puma, Reebok, New Balance, ASICS, Converse, Vans, Under Armour,
Skechers, FILA, Salomon, HOKA, On и Brooks.

**Подтверждённый локальный тест 25.09.2026:** опубликованы 24 карточки со
161 вариантом размера от **Puma, Reebok, FILA, On и Brooks**. Это результат
конкретного запуска, а не постоянное количество товаров или гарантия доступности магазинов.

Для остальных десяти источников в проверках обнаружены блокировки, проверки браузера
или ограничения доступа к данным вариантов. Например, Skechers отдаёт страницу
товара, но используемые запросы выбора размеров ограничены robots.txt. Наличие
парсера в проекте не означает работающий импорт этого бренда.

Также реализованы адаптеры разрешённых товарных фидов: JSON, YML, Awin CSV,
Google Merchant XML/CSV; предусмотрены eBay и профили дополнительных ретейлеров.
Они требуют отдельной настройки и прав доступа. Исследованная интеграция KicksDB
не используется как источник подтверждённых фиксированных скидочных предложений
в текущем реестре адаптеров.

## 6. Цены и валюты

Для каждого предложения сохраняются исходная валюта, первоначальная и сниженная
цены, цены размеров, время проверки и результат конвертации в KZT.

Провайдер курса по умолчанию — **Национальный банк Казахстана**, `RATE_PROVIDER=nbk`.
Также предусмотрены ручной курс и разрешённый JSON-источник с явной маркировкой.
Источник, значение и время курса сохраняются вместе с предложением.

Действующий официальный API Kaspi для этой задачи не подключён. Проект не выдаёт
курс другого провайдера за курс Kaspi. Изменение провайдера выполняется настройками
окружения; недостающий или просроченный курс не заменяется вымышленным значением.

## 7. Хранение данных и защита

Основные таблицы SeaTable:

- `STEPPE_Scrapes` — отчёты сборщиков и исходные товарные данные.
- `STEPPE_Sources` — реестр источников и состояние паузы.
- `STEPPE_Offers` — предложения в снимках публикации.
- `STEPPE_Runs` — результаты импорта и сведения о курсах.
- `STEPPE_Users`, `STEPPE_Sessions`, `STEPPE_AuthAttempts` — пользователи,
  сессии и учёт попыток входа.

Публикация использует неизменяемые проверенные снимки. Незавершённая запись не
считается успешным импортом. В SeaTable нет полноценной распределённой транзакционной
блокировки для этого процесса; параллельные обновления увеличивают расход API-квоты.

Пароли хешируются через scrypt; сессии используют HttpOnly cookie.
Служебные API импорта защищены `CRON_SECRET`. Токены базы, реальные `.env`-файлы,
списки прокси и локальные диагностические артефакты исключены из Git.

## 9. Запуск и сопровождение

Для разработки нужны Node.js 22+ и Python 3.12+ для Python-парсеров.
Создайте `.env.local` по образцу `.env.example`, сохранив реальные секреты только локально.

```powershell
npm ci
python -m pip install -r scripts/python-sale/requirements.txt
npm run dev
```

Настройка базы: `npm run seatable:setup`; проверка подключения: `npm run seatable:check`.
Для локального планировщика отдельно требуется `.env.scheduler.local` — подробности
в инструкции ниже. Браузер локальной задачи устанавливается в собственный кэш.

Ручной запуск **с отправкой результата на production-сайт**:

```powershell
node scripts/local-refresh.mjs
```

Проверки кода:

```powershell
npm run typecheck
npm test
npm run test:e2e
python -m unittest discover -s scripts/python-sale -p 'test_*.py'
```

Для браузерных тестов предварительно установите Chromium командой
`npx playwright install chromium`. Журналы локального обновления находятся в
`artifacts/local-refresh/`, сводка последнего запуска — `latest.json`.
Облачные журналы и артефакты доступны в GitHub Actions.
